# Memora 智能问答工作台改版设计

## 目标

修复智能问答页面左侧区域缺少有效交互反馈、中央视觉层级松散、右侧执行过程文字被遮挡的问题。在不改变现有问答与 Agent 数据链路的前提下，将页面整理为可操作、聚焦且信息完整的三栏工作台。

## 已确认方向

采用「A · 平衡工作台」：保留完整三栏，左侧负责会话管理，中间负责提问与回答，右侧负责 Agent 执行过程。新用户默认展开右侧面板。

## 布局设计

### 左侧会话栏

- 默认宽度约 280px，保持稳定，不与中央消息区争抢空间。
- 顶部包含标题、真实可用的会话搜索输入框和新建按钮。
- 右上角 `+`、空状态整块区域以及明确的“新建会话”按钮均触发同一新建行为。
- 会话项继续支持选中和删除，并补充清晰的 hover、active、focus 和 loading 状态。
- 搜索在本地按已加载的会话标题过滤；清空搜索词后恢复完整列表。

### 中间问答区

- 中间区域占据剩余可用宽度，消息正文与输入框使用一致的最大宽度和水平对齐。
- 空会话欢迎内容上移并压缩垂直留白，突出标题、简短说明和四个建议问题。
- 建议问题卡片为真实按钮；点击后只把内容写入输入框，不自动发送。
- 输入框固定在底部，通过边框、阴影、背景层次和发送按钮建立明确操作焦点。
- 已有提问、停止生成、断线重连、消息滚动与引用行为保持不变。

### 右侧执行面板

- 新用户默认展开，默认宽度约 360px，可在 320–480px 范围拖动。
- 标题区为收起按钮预留空间，标题和说明不得与按钮重叠。
- 步骤、工具名称、错误信息和资源用量允许自动换行；长标识使用 `overflow-wrap: anywhere`。
- 面板内容区独立纵向滚动，外层不裁剪有意义的文本。
- 无任务时展示简洁说明；运行中按事件顺序展示 Router、工具调用、状态和资源用量。
- 收起状态及调整后的宽度继续保存在本地存储。

## 组件与职责

### `ConversationSidebar.vue`

负责搜索词、过滤后的会话列表、空状态 CTA、新建与删除交互。新建入口统一调用现有创建 mutation，成功后通过 `select` 事件进入新会话。

### `MessageList.vue`

负责消息流与空会话欢迎区。建议问题通过事件向上抛出，不直接访问输入框或发送 API。

### `ChatComposer.vue`

继续拥有输入文本与提交行为，新增可由父组件设置的草稿值接口。收到建议问题后填入草稿并聚焦输入框，不自动提交。

### `ChatPage.vue`

连接建议问题事件与输入框草稿，同时保留现有会话创建、消息提交、SSE 和 Agent 运行状态流程。

### `ChatWorkspaceShell.vue`

负责三栏尺寸、右侧拖动范围、收起/展开结构和溢出边界。不得承担会话或 Agent 业务逻辑。

### `AgentRunPanel.vue`

负责执行步骤的可读呈现，确保文本换行、内容滚动和无任务状态完整显示。

## 数据流

### 新建会话

1. 用户点击 `+`、空状态或“新建会话”。
2. `ConversationSidebar` 调用现有创建 mutation，并禁用所有新建入口避免重复请求。
3. 创建成功后发出 `select(conversationId)`。
4. `ChatPage` 更新路由并选中新会话。
5. 创建失败时保留当前页面，由现有全局通知系统显示错误。

### 建议问题

1. 用户点击建议问题卡片。
2. `MessageList` 发出建议文本事件。
3. `ChatPage` 将文本传给 `ChatComposer` 的草稿接口。
4. `ChatComposer` 更新输入值并聚焦 textarea。
5. 用户主动点击发送或使用快捷键后，才进入现有提交流程。

### 会话搜索

1. 用户输入搜索词。
2. `ConversationSidebar` 对已加载会话标题进行不区分大小写的本地过滤。
3. 无匹配结果时显示“未找到会话”，但保留新建入口。

## 错误与边界状态

- 新建会话期间显示 loading，并阻止重复创建。
- 搜索无结果与真正没有会话使用不同文案。
- 建议问题在输入框禁用时仍可填入草稿，但不能绕过已有发送禁用条件。
- 右侧极长连续字符不得扩大面板或挤压中央区域。
- 视口空间不足时优先维持中央问答的最小可用宽度；右侧仍可手动收起。

## 可访问性

- 搜索框、空状态 CTA、建议问题卡片和面板收起按钮均使用原生可聚焦控件。
- 所有图标按钮提供明确的 `aria-label`。
- 当前会话使用 `aria-current` 或等价选中语义。
- 键盘用户可完成搜索、新建、选择建议问题、发送和收起面板。

## 测试策略

- `ConversationSidebar`：验证三个新建入口触发同一行为、创建期间防重复、搜索过滤和无匹配状态。
- `MessageList` / `ChatComposer`：验证建议问题写入草稿、聚焦输入框且不会自动提交。
- `ChatWorkspaceShell` / layout store：验证右栏默认展开、宽度范围为 320–480px、拖动结果持久化。
- `AgentRunPanel`：验证长工具名和长错误信息使用可换行容器，步骤区域可滚动。
- 现有聊天语义、消息提交、停止生成和路由测试继续通过。

## 非目标

- 不修改后端会话、消息或 Agent API。
- 不重构 SSE 事件协议或 Agent 运行状态模型。
- 不加入跨知识库会话搜索。
- 不引入新的设计系统或第三方 UI 依赖。

## 验收标准

- 左侧所有呈现为可操作的入口均有实际行为和即时反馈。
- 中央空状态在常见桌面尺寸下层级紧凑、建议问题可用、输入区醒目。
- 右侧标题不被按钮遮挡，任意长文本不会横向溢出或被截断。
- 从空会话到新建、输入建议问题、发送和查看执行过程的完整流程可用。
- 所有新增回归测试、现有测试、类型检查、Lint 与生产构建通过。
