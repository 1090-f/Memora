# Memora 沉浸式前端改版设计

> 日期：2026-08-01  
> 状态：已获用户授权直接实施  
> 范围：桌面端 Vue 3 前端视觉系统、核心工作区与管理页统一规范

## 1. 目标

将现有 Memora 从传统管理后台视觉升级为沉浸式个人知识工作台。页面需要具有明确的 AI 产品气质，同时保证文档阅读、长列表、表单配置和 Agent 运行轨迹的可读性。

验收成功标准：

- 全站形成统一、可识别的紫蓝品牌视觉，不再依赖零散 Tailwind 类拼接出页面风格；
- 智能问答页默认突出消息正文，Agent 运行详情可按需展开；
- 文档页默认突出正文阅读，当前文档 AI 可发现、可展开但不抢占阅读空间；
- 知识库和其他管理页共享统一的页面标题、卡片、状态、表单和空状态语言；
- 1280、1440、1920 像素桌面宽度下保持关键操作可达；
- 动效遵守 `prefers-reduced-motion`，正文和交互对比度满足 WCAG AA 的基础要求。

## 2. 已确认的设计方向

### 2.1 B2：平衡沉浸

- 应用背景使用低饱和紫蓝环境光；
- 框架、侧栏和浮层可使用半透明表面及轻量背景模糊；
- 文档正文、表格、表单和长列表自动收敛为接近纯白的高可读表面；
- 不使用高饱和大面积渐变，不把玻璃效果嵌套超过两层；
- 紫色用于品牌、主操作、AI 和选中状态，蓝色主要用于环境光及运行状态。

### 2.2 L2：专注问答

- 会话列表常驻；
- 中央消息区是默认视觉中心；
- Agent 检查器收起时仅显示紧凑状态入口，展开后约 360 像素宽；
- 运行轨迹包含 Router、Plan/ReAct、工具调用、Token、耗时、引用及最终状态；
- 流式输出期间输入框持续可见，停止后保留已经生成的内容。

### 2.3 D2：阅读优先

- 知识库目录树常驻；
- 正文采用稳定的纸张表面和 760–820 像素阅读宽度；
- 当前文档 AI 收起时保留明确入口，展开后约 360 像素宽；
- AI 面板始终显示当前作用域，禁止把知识库问答误标为仅基于当前文档；
- 从引用跳转到文档时定位章节、突出引用文本，并保留返回原会话入口。

## 3. 全局页面骨架

```text
60px 全局导航
├── 品牌入口与知识库切换
├── 智能问答、文档、运行记录、长期记忆、MCP、设置
└── 全局搜索与用户菜单

页面区域
├── 64px 页面标题栏
├── 248–272px 可选业务侧栏
├── 自适应主内容区
└── 48–56px 收起 / 360px 展开的 AI 或 Agent 检查器
```

- 聊天正文最大宽度约 880 像素；
- 文档正文最大宽度 820 像素；
- 管理页面最大宽度 1440 像素；
- 低于 1280 像素时优先收起右侧检查器，再收起业务侧栏；
- P0 不实现完整移动端，但提供基础降级布局，不显示阻断式“不支持”页面。

## 4. 视觉系统

### 4.1 颜色与表面

- 品牌主色：`#7C3AED`；品牌深色：`#6D28D9`；
- 紫蓝环境光：`#C4B5FD`、`#BFDBFE`，只作为低透明度装饰层；
- 应用底色：`#F5F3FA`；高可读表面：不低于 `rgba(255,255,255,0.92)`；
- 导航底色：深紫黑 `#17131F`；
- 主文字：`#211D2B`；次级文字：`#716A7C`；边界：`rgba(88,72,112,0.14)`；
- 成功、运行、警告、失败必须同时使用图标或文本，不能只依靠颜色。

### 4.2 字体、间距和圆角

- 字体栈：`Inter, "Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif`；
- 页面标题 22–24px，区块标题 16px，正文 14px，辅助文字 12px；
- 间距使用 4px 基础网格；
- 控件圆角 8px，普通卡片 12px，主要容器 16px，禁止继续增加新的圆角层级；
- 按钮和输入框默认高度 36–40px；核心点击区域不小于 40×40px。

### 4.3 层次与动效

- 结构主要通过表面透明度、边界和留白区分；
- 普通卡片只使用轻阴影，悬浮层和焦点输入区可以使用中等阴影；
- 页面进入、侧栏展开和浮层出现使用 160–220ms 缓动；
- `prefers-reduced-motion: reduce` 时关闭位移、缩放和背景漂移动效。

## 5. 页面设计

### 5.1 智能问答

- 欢迎态显示当前知识库、简短引导、推荐问题和主输入框；
- 消息气泡仅用于用户消息，AI 回答使用无气泡正文，减少视觉噪声；
- 引用以内联编号和来源卡片呈现，知识库引用与网页引用图标不同；
- 收起的 Agent 入口显示阶段、进度和最终状态，展开后显示完整时间线；
- 输入区固定在消息区底部，使用高可读半透明表面。

### 5.2 文档工作区

- 左侧包含知识库切换、搜索、导入和目录树；
- 顶栏包含面包屑、状态、更新时间、返回会话和更多操作；
- 正文表面保持接近纯白，环境光不穿透正文内容；
- 右侧 AI 入口显示“询问当前文档”，展开后显示文档标题和作用域；
- 处理、失败、空内容和无权限均保留完整页面骨架。

### 5.3 知识库与管理页

- 知识库首页使用概览头部、搜索筛选和响应式卡片网格；
- 卡片突出名称、说明、文档数量、更新时间和主要操作，不使用装饰性大图；
- 运行记录、Memory、MCP、模型配置和个人设置共享 `PageHeader`、`SurfaceCard`、`FilterBar`、`StatusBadge`、`EmptyState`；
- 设置页使用左侧设置分组或顶部标签，表单宽度限制在 720–800 像素；
- 登录页采用 B2 品牌氛围，但表单本身保持简洁和高对比度。

## 6. 组件边界

- `AppShell`：环境背景、全局导航、全局搜索、知识库切换和用户入口；
- `WorkspaceHeader`：标题、上下文、状态与主要操作；
- `WorkspaceSidebar`：统一侧栏表面、折叠和宽度行为；
- `InspectorRail`：收起状态入口及展开按钮；
- `SurfaceCard`：管理页通用卡片表面；
- `PageContainer`：管理页最大宽度与响应式内边距；
- 现有业务组件继续负责数据和行为，视觉组件不直接发起 API 请求。

## 7. 数据流与状态

- 服务端数据继续由 TanStack Vue Query 管理；
- 登录用户、当前知识库和跨页面布局偏好继续由 Pinia 管理；
- 会话、文档和 Agent 业务数据不迁入纯视觉组件；
- 侧栏宽度、折叠状态和用户的减弱动效偏好保存在本地；
- SSE 中断、重连和最终结果确认沿用现有运行时 Store，不改变接口契约。

## 8. 异常与降级

- 所有主页面必须有加载、空数据、错误、无权限和就绪状态；
- 错误展示用户可理解的摘要、重试按钮和可复制 `request_id`；
- 玻璃模糊不受支持时降级为不透明浅色表面；
- 低于 1280 像素时折叠非核心面板，不阻断用户进入页面；
- 环境光为纯装饰层，必须设置 `pointer-events: none` 和 `aria-hidden`。

## 9. 验证

- 为布局状态、导航激活和检查器折叠等行为增加组件或单元测试；
- 运行 TypeScript 类型检查、ESLint 和生产构建；
- 在 1280、1440、1920 像素宽度检查智能问答、文档、知识库、管理页和登录页；
- 检查键盘焦点、弹层焦点恢复、文本对比度和减弱动效；
- 验证加载、空状态、错误、无权限、SSE 中断和执行失败不会破坏页面骨架。

## 10. 实施边界

本轮不改变后端 API、数据库、Agent 业务语义和路由地址；不实现完整移动端、暗色主题、富文本编辑器或新的 Agent 工作流。改动重点是设计 Token、全局壳层、核心工作区和共享页面组件。
